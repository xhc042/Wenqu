## 一、目标对照与差距分析

| 模式 | 用户期望 | 现有实现 | 主要差距 |
|------|----------|----------|---------|
| 🚀 速读 | 快速学完全书，抓住最重要知识点 | 仅提取目录+首尾段，不生成掌握项，全部懒加载 | 缺乏知识点提炼、核心总结和快速验证机制，仅提供"目录预览" |
| 📖 细读 | 标准掌握全书知识点 | 全文前5000字，生成标准掌握项，全部预加载 | 掌握项列表与学习过程脱节，缺乏知识点覆盖度追踪和练习环节；内容截断导致后半本书丢失 |
| 🔬 研读 | 深度掌握全书知识点，辩证分析 | 保留全文，生成深度掌握项+苏格拉底追问，预加载3章 | 辩证分析依赖LLM自由发挥，缺乏结构化框架（如正反对比、逻辑链检查） |

## 二、核心问题诊断

### 问题一：速读模式实际上没有"学"任何东西

**现状**：
- 速读只提取目录结构和每章首尾段（[chunker.py#L549-L551](file:///d:/Tiger/Wenqu%20v1.1/chunker.py#L549-L551)）
- 不生成掌握项（[app.py#L480-L482](file:///d:/Tiger/Wenqu%20v1.1/app.py#L480-L482)）
- 全部懒加载，用户看到的只是章节标题列表

**问题本质**：速读的初衷是"快速建立知识地图，决定是否深入"，但这只是一个侦察模式，不是学习模式。如果想通过速读"快速学完最重要的知识点"，现有设计完全达不到这个目标。

### 问题二：细读模式缺乏"全书知识点覆盖"机制

**现状**：
- 细读虽然生成了掌握项（syllabus），但每章只有6轮对话（30分钟）
- 掌握项可能有多条，但对话轮次有限，无法逐一攻克
- 没有"全书知识点进度总览"的概念
- 内容仅截取前5000字符，后半本书完全丢失

**问题本质**：细读模式是"逐章推进"的线性流程，但缺乏知识点维度的追踪和覆盖保证。用户可能学完一章又一章，但不知道哪些知识点已经掌握，哪些还没有。

### 问题三：研读模式缺乏"辩证分析"能力

**现状**：
- 研读模式虽然有苏格拉底追问（[config.py#L111](file:///d:/Tiger/Wenqu%20v1.1/config.py#L111)），但仅限于单章内部
- 跨章节的对比分析依赖"前序章节摘要"（[state_machine.py#L103-L106](file:///d:/Tiger/Wenqu%20v1.1/state_machine.py#L103-L106)），但只在PROBE阶段微弱体现
- 没有专门的"批判性思维"或"辩证分析"触发机制

**问题本质**：深度掌握不等于苏格拉底追问。真正的"深度掌握+辩证分析"需要：
1. 跨章节的知识关联
2. 对作者观点的批判性质疑
3. 不同章节之间的矛盾/统一关系分析

### 问题四：学习时长选项与实际学习效果脱钩

**现状**：
- 15/30/60分钟只映射到最小对话轮次（[state_machine.py#L113-L116](file:///d:/Tiger/Wenqu%20v1.1/state_machine.py#L113-L116)）
- 没有考虑章节难度、知识点数量、掌握状态

**问题本质**：学习时长应该是结果导向的（掌握多少知识点），而不是过程导向的（对话几轮）。一个复杂的章节需要60分钟，一个简单的章节15分钟就够了，但现有设计对所有章节一视同仁。

### 问题五：模式与学习契约相互独立

**现状**：
- 用户选择速读模式后，仍可以选择deep深度+60分钟，造成体验割裂
- 没有根据模式自动推荐合理的契约默认值

**问题本质**：速读/细读/研读与认知深度、学习时长是独立的配置项，缺乏联动机制。

### 方案一：速读模式优化 —— "知识快照 + 全局精华"双轨制

### 方案二：细读模式优化 —— "掌握项绑定 + 均匀采样 + 覆盖度追踪"

**核心思路**：结合"掌握项绑定对话"和"均匀采样"的优点，以及"知识点覆盖追踪"的理念。

#### 3.2.1 细读均匀采样策略

```python
# chunker.py - 修改 standard 模式下的内容采样
def sample_chapter_fairly(text: str, target_chars: int = 5000) -> str:
    """
    按章节均匀采样，保证全书代表性
    不是只取前5000字，而是每章取固定比例
    """
    paragraphs = [p.strip() for p in text.split('\n\n') if p.strip()]
    if not paragraphs:
        return text[:target_chars]
    
    # 按比例分配每章的字符数
    chars_per_para = target_chars / len(paragraphs)
    sampled = []
    current_chars = 0
    
    for para in paragraphs:
        if current_chars >= target_chars:
            break
        # 每章至少取1段，最多取全部
        sampled.append(para)
        current_chars += len(para)
    
    return '\n\n'.join(sampled)
```

```python
# state_machine.py - 新增覆盖检测
def _check_knowledge_coverage(self) -> dict:
    """
    检查当前章节的知识点覆盖情况
    返回：哪些知识点已掌握、哪些还需要强化
    """
    chapter_items = [s for s in self.syllabus_items 
                     if s["chapter_index"] == self.chapter_index]
    
    coverage = {
        "total": len(chapter_items),
        "mastered": sum(1 for s in chapter_items if s["status"] == "mastered"),
        "in_progress": sum(1 for s in chapter_items if s["status"] == "in_progress"),
        "pending": sum(1 for s in chapter_items if s["status"] == "pending"),
    }
    
    # 如果本章还有pending项，提示用户继续学习
    if coverage["pending"] > 0 and coverage["mastered"] > 0:
        return {"partial": True, "suggestion": f"本章还有{coverage['pending']}个知识点未掌握"}
    
    return coverage
```

#### 3.3.2 反方辩论子模式

```python
# state_machine.py - 新增 DEBATE 状态
DEBATE = "DEBATE"

async def _check_debate_trigger(self, user_text: str) -> bool:
    """
    检测是否触发反方辩论
    条件：学生连续两次完全认同教师观点
    """
    # 简化版：检测用户回复中是否频繁出现"是的"、"对"、"有道理"等认同词汇
    agreement_keywords = ["是的", "对", "有道理", "没错", "你说得对", "确实"]
    agreement_count = sum(1 for kw in agreement_keywords if kw in user_text)
    
    # 如果认同词汇超过2个，且当前轮次>2，触发辩论
    return agreement_count >= 2 and self.current_round > 2

async def _start_debate(self) -> AsyncGenerator[str, None]:
    """
    切换到反方角色，提出对立观点
    """
    self.state = self.DEBATE
    
    debate_prompt = f"""
    现在请你扮演与本章节观点对立的学者。
    针对刚才讨论的内容，提出一个有力的反对观点。
    
    要求：
    - 必须基于教材内容，不能凭空捏造
    - 观点要有学术依据，不能是情绪化反驳
    - 最后要求学生思考：哪种观点更有说服力？为什么？
    """
    
    self.messages.append({"role": "user", "content": debate_prompt})
    
    content_parts = []
    async for chunk in llm.chat_stream(self.messages, temperature=0.9):
        content_parts.append(chunk)
        yield chunk
    
    full_content = "".join(content_parts)
    self.messages.append({"role": "assistant", "content": full_content})
```

#### 3.4.2 动态学习目标设定

```python
# state_machine.py - 修改初始化逻辑
def _set_learning_target(self) -> dict:
    """
    根据模式和时长，动态设定学习目标
    """
    reading_mode = self.course_info.get("reading_mode", "standard")
    mode_defaults = MODE_CONTRACT_DEFAULTS.get(reading_mode, MODE_CONTRACT_DEFAULTS["standard"])
    
    if reading_mode == "speed":
        # 速读：目标是掌握最重要的N个知识点
        remaining_items = [s for s in self.syllabus_items 
                           if s["status"] != "mastered"]
        target_count = min(5, len(remaining_items))  # 最多5个核心知识点
    elif reading_mode == "standard":
        # 细读：目标是完成当前章节的所有掌握项
        remaining_items = [s for s in self.syllabus_items
                           if s["chapter_index"] == self.chapter_index
                           and s["status"] != "mastered"]
        target_count = len(remaining_items)
    else:
        # 研读：目标是深度理解+辩证分析
        target_count = "unlimited"  # 不设上限，直到完成辩证分析
    
    return {
        "target_count": target_count,
        "goal": mode_defaults["goal"],
        "expected_output": mode_defaults["expected_output"],
    }
```

## 五、风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 速读快照+全局提炼增加LLM调用次数 | 成本上升 | 快照用fast tier，全局提炼只做一次，结果缓存 |
| 反方辩论可能偏离学习主线 | 体验混乱 | 辩论触发条件严格限制（连续2次认同+轮次>2），辩论后必须回归主线 |
| 均匀采样可能丢失关键论证 | 理解不完整 | 采样比例可调（细读20%，研读50%），关键章节全文保留 |
| 前端知识地图开发周期长 | 延期交付 | 先用简单列表+颜色标注，后续再升级为可视化图表 |
| 模式-契约联动可能限制灵活性 | 高级用户不满 | 联动仅为默认值，允许用户手动调整 |
| 向后兼容 | 已有课程行为改变 | 保留旧行为作为可选配置，新默认值仅对新课程生效 |

## 七、核心优化原则总结

1. **速读抓核心**：通过"知识快照+全局精华"双轨制，让用户在30分钟内掌握全书最重要的5-10个知识点
2. **细读全覆盖**：通过"均匀采样+掌握项绑定+覆盖度追踪"，确保全书知识点不被遗漏，进度可衡量
3. **研读能辩证**：通过"辩证框架+反方辩论+思辨笔记"，真正实现批判性思考和深度理解
4. **模式联动契约**：速读/细读/研读与认知深度、学习时长智能联动，减少用户配置负担
5. **目标导向时长**：学习时长决定学习目标而非对话轮次，更灵活也更贴合实际需求
