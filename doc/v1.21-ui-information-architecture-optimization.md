# 问渠（Wenqu）v1.21 UI 信息架构与展示层优化 - 产品开发说明书

> **文档版本**：v1.21
> **生成时间**：2026-07-02
> **需求来源**：用户在课程详情页提报的展示层 / 操作入口问题反馈
> **代码基准**：问渠 v1.1 现有代码库（`app.py` / `state_machine.py` / `static/js/app.js` / `static/index.html`）
> **适配 rein 视角**：`reading-mentor`（产品主视角）→ `developer` / `prompt-engineer` / `db-migrator`（实施）→ `tester` / `code-reviewer`（验证）
> **配套文档**：`AGENTS.md` §产品愿景（L1/L2/L3 定位）、§PR & commit conventions

## 一、需求概述

### 1.1 一句话目标

**把课程详情相关的展示层从"什么都堆"的 dashboard，重组为以"用户下一动作"为锚的极简决策辅助。** 不是单点美化，而是一次以 reading-mentor 视角为牵引的信息架构重整。

### 1.2 用户原始反馈

| # | 反馈要点 | 形态 |
|---|---|---|
| 1 | 章节列表下面信息太多、有重复 | 同一字段三遍（🎯 / 💡 / 关键词），"快速浏览即可"vs"重要/精华"信号打架 |
| 2 | 所有章节都显示"精华知识点 + 快速浏览"，逻辑错乱 | 决策信号与状态信号混用，缺乏派生判断 |
| 3 | 知识快照 + 全书总览信息多有重叠 | 同一份 LLM 数据渲染两遍，互为冗余 |
| 4 | 全书知识点是个平铺长列表，无法按维度过滤 | 没有"还差多少到结业"的视角 |
| 5 | 风格调控与课程耦合，每个课重设一次 | 体验错位：风格跟随用户，不跟随书 |
| 6 | 课程详情里塞了一个「🔧 模型配置」 | 全局开发者配置错位到学员场景 |

### 1.3 优化原则（L1/L2/L3 定位自检）

| 原则 | 含义 |
|---|---|
| **L3 优先** | 问渠主攻 L3（"读会用"），所有改动必须问一句："这功能帮用户'读完'还是'会用'？"。能助其形成判断的优先；纯展示的不留 |
| **决策辅助优先于展示** | 列表页 / 弹窗存在的唯一价值是帮用户在 5 秒内形成"下一步做什么"的判断 |
| **同义信息只露一条** | LLM 多 prompt 同源字段（learning_goal / core_viewpoint）、不同视图展示相同数据——前端要挑最关键的那一条 |
| **开发 / 全局配置不混进学员场景** | 模型配置 / 高级调试项归左导航 + 设置菜单，课程详情头不允许出现 |
| **强互动 / 强黏性模块前置** | "我下一步学哪"这种 L3 主信号应放到最显眼位置；纯列举式查看放弹窗 |

## 二、现状诊断（含现场证据）

### 2.1 课程详情头部 —— 8 个按钮一字排开

**现场**：`static/js/app.js:1062-1071`

```javascript
<button ... onclick="showCourseOverview()">📊 全书总览</button>
<button ... onclick="showSnapshotsModal()">🚀 知识快照</button>  // 仅 speed
<button ... onclick="showSpiritualNotesModal()">🧠 思辨笔记</button> // 仅 deep
<button ... onclick="showContractModal()">📋 学习契约</button>
<button ... onclick="showSlidersModal()">🎛️ 风格调控</button>
<button ... onclick="switchView('model-config');...">🔧 模型配置</button>
<button ... onclick="showAllSyllabusModal()">📋 全书知识点</button>
<button ... onclick="deleteCurrentCourse()">🗑️</button>
```

**问题**：
- 8 个按钮同时可见、视觉权重相同
- 学员用的高频（全书总览）和开发者用的低频（模型配置）并列
- 进入课程的第一屏是"一堆按钮"，学员选择困难

### 2.2 章节列表（速读模式）—— 信息冗余 + 决策错位

**现场**：`static/js/app.js:1183-1256`

每章节渲染 6-8 块文字，包括：
1. 标题 + 3 个 tag（⭐ 核心 / 🔥 重要 / 📋 精华知识点）
2. 🎯 `learning_goal` + 💡 `core_viewpoint`（同 LLM 同 prompt 出的两段近义文字）
3. `keywords` 标签行
4. `sessionCount > 0 ? "已学习 N 次" : "💡 快速浏览即可"` ← 状态信号
5. `mastered/total 项掌握` 进度
6. 每掌握项的迷你 chip + 标记按钮
7. 操作按钮

**问题**：
- 🎯 + 💡 字段近义，LLM 来源同 prompt，前端未去重
- "⭐ 核心 + 🔥 重要 + 📋 精华" 多 tag 同时出，信号相互稀释
- "💡 快速浏览即可"与"⭐ 核心"打架——同一章节既说核心又说不用管
- 单章节 6-8 块文字，首屏仅能装下 2-3 章

### 2.3 知识快照 + 全书总览 —— 同一份数据两遍渲染

| 视图 | 来源字段 | 渲染位置 |
|---|---|---|
| `🚀 知识快照` 弹窗 —— "全书核心知识点" | `overview.highlights.key_points` | `app.js:3615-3635` |
| `📊 全书总览` 弹窗 —— "🔥 全书核心知识点" | `overview.highlights.key_points` | `app.js:3712-3727` |

**问题**：
- 同字段同渲染逻辑两处复制（🔴 核心 + 📌 重要标签、卡片宽度、字号一致）
- "各章知识快照"（快照弹窗）与主页章节列表信息几乎一模一样
- 用户开两个弹窗其中之一基本是浪费点击

### 2.4 全书知识点 —— 平铺列表

**现场**：`static/js/app.js:3377-3468`（`showAllSyllabusModal`）

```text
[第 1 个知识点] [章节名]                       [✓ 我已掌握] [待学习]
   能解释 ETF 的定义、交易机制及主要特点
[第 2 个知识点] ...
```

**问题**：
- 全书混排一列，60 个掌握项要滚很久
- 没有按章节分组 / 按状态筛选 / 按重要性排序
- 顶部"🔄 刷新知识点"按钮暗示"经常刷新"——实际上 LLM 一次生成完基本不会再刷新
- 没有"我离结业还差多少"的差量视图

### 2.5 风格调控 —— 课程级存储 + 学员场景高曝光

**现场**：`static/index.html:304-334`（弹窗定义） + `static/js/app.js:1501-1555`（函数） + API `POST /api/courses/{id}/sliders/{role}`

**问题**：
- **存储位置错位**：滑块配置按课程存储（`course_id` 路由），用户换课程要重设
- **角色下拉 8 个角色** —— power user 思维，学员看不懂
- **三滑块都是 -5 到 +5** —— 普通用户面对 ±5 区间会懵
- **入口在课程详情头部** —— 学员进课程第一个看到的按钮之一，错了优先级

### 2.6 模型配置 —— 全局配置错位到课程详情

**现场**：
- 课程详情按钮：`app.js:1068`（要干掉）
- 独立左导航：`static/index.html:31-33`（保留）
- 模型配置页：`static/index.html:253-256`，`app.js:3064-3314`

**问题**：模型配置是全局的、开发者/管理员级操作，**进课程详情**这个学员场景里没有任何理由出现这个按钮。

## 三、目标架构

### 3.1 课程详情头部 —— 按角色分层折叠

```
[课程标题........]   [📋 学习契约]   [⚙️ 设置菜单 ▾]
                                       ├─ 🎛️ 风格调控
                                       ├─ 🧠 思辨笔记（仅 deep）
                                       ├─ 🚀 知识快照（仅 speed）
                                       ├─ 📋 全书知识点
                                       └─ 🗑️ 删除课程

[📊 全书总览]    ← L3 决策辅助：常驻高频
```

**目标**：8 个按钮折叠为 **5 个元素**（含 1 个菜单），首屏一行看全。

### 3.2 章节列表（速读模式）—— 决策信号化

每章节从 6-8 块文字降到 **3 块**：

```
📖 ETF 基础认知                                ⭐ 核心 · 5 知识点
  💡 帮你建立 ETF 基础认知，理解其定义、特征与核心优势
  [快速浏览]
```

**派生信号**（前端计算，无需新接口）：
- `suggestedAction` ∈ `{已掌握可跳过, 推荐精读, 快速了解, 建议重学}`
- 单 tag 优先级：`is_core > importance ≥ 4 > 有掌握项`

### 3.3 知识快照 —— 合并 / 砍

**决策**：
- 砍掉独立的 `🚀 知识快照` 按钮 + 弹窗
- 总览弹窗接管其核心信息（"全书核心知识点"）
- 主页章节列表接管"各章知识快照"

### 3.4 全书总览 —— 瘦身 + 接住快照

新结构（弹窗内 5 块）：

```
[📊 全书总览]                                            [✕]
─────────────────────────────────────────────────────────
┌──────────────┬──────────────┐
│   68%        │   12 章      │   ← 进展 + 规模
│   掌握率     │   7 已学     │
└──────────────┴──────────────┘

🎯 立即学习                                               ← L3 主信号
   第 3 章「ETF 交易机制」
   💡 掌握 ETF 二级市场交易规则，理解折溢价机制
   [开始学习 →]

🔥 全书核心（3 件你必须知道的）                            ← L3 决策锚
   ① ETF 是一篮子股票 / ② 核心-卫星策略 / ③ 折溢价机制
   + 还有 5 条重要观点 ⌄

📊 章节进度（仅显示有进度的 5-8 章）                        ← 收敛
   第 1 章 ████████░░ 80%
   第 2 章 ██████░░░░ 60%
   ...

💡 AI 建议（最近一次学习后的简短反馈）                     ← 单行
```

**砍掉**：
- 📊 完整章节进度条列表（与主页重叠）
- ✅ 已学习小章 chip 列表（主页面板覆盖）
- 🔁 重复的 `🔴 核心待学` 列表（已被"立即学习"取代）

### 3.5 全书知识点 —— 差量进度视图

```
📋 全书知识点
─────────────────────────────────────
结业门槛:   50 项核心 ✓ 已掌握 28/50 (56%)
                     [🔥 还差 22 项，点击补齐]

[全部] [⏳待学习] [✅已掌握]                   ← 状态过滤

📚 按章节:
  第 1 章 ETF 基础        8/10  ✓ [全部掌握]
  第 2 章 交易机制        6/12  ⚠ 差 6 [补齐]
  第 3 章 投资策略        3/8   ⚠ 差 5 [补齐]
  ...
```

**关键改动**：
- 顶部加 3 个状态过滤器：`全部 / ⏳待学习 / ✅已掌握`
- 按章节分组 + 每章节掌握度汇总
- 显示"差量进度"（L3 主信号）
- 顶部 `🔄 刷新知识点` 按钮降级到 `⚙️ 设置菜单`（开发选项，普通用户不点）

### 3.6 风格调控 —— 用户级存储 + 入口降级

**改动**：
- **存储**：从 `course_id` 维度改为 `user_id` 维度（同角色一套设置跨课程复用）
- **入口**：从课程详情头部移到 `⚙️ 设置菜单`
- **UI**：在 ±5 滑块之上加 3-4 档预置档位（"🎯 像老师 / 像朋友 / 像辩论对手"），高级用户能展开自定义
- **默认值**：`0`（中位）就够。第一次进课程不询问，用户主动来设

### 3.7 模型配置（课程详情）—— 直接删除

```diff
- <button class="btn btn-outline btn-sm" onclick="switchView('model-config');loadModelConfig()">🔧 模型配置</button>
```

独立页面 / 左导航保留。开发改 schema 时同步检查是否还有别处有引用。

## 四、实施切分（按风险与依赖排序）

> 切片原则：**纯前端 → 后端存储调整 → 跨 rein 边界**。每一片都能独立 commit、独立 reviewer。

### 4.1 切片 A：纯前端 UI 瘦身（无 schema / prompt 变更）

**文件范围**：
- `static/js/app.js:1062-1071`（按钮组）
- `static/js/app.js:1183-1256`（章节列表渲染）
- `static/js/app.js:3615-3665`（知识快照弹窗）
- `static/js/app.js:3678-3823`（全书总览弹窗）
- `static/js/app.js:3377-3468`（全书知识点弹窗）
- `static/index.html`（教学风格滑块弹窗结构 + ⚙️ 菜单容器）

**改动清单**：
1. 删除课程详情头部的 `🔧 模型配置` 按钮（验证左导航可达）
2. 课程详情头部剩余按钮折叠为 `⚙️ 设置菜单`（含 🎛️ / 🧠 / 🚀 / 📋 / 🗑️）+ 保留 📊 全书总览 + 📋 学习契约 为常驻按钮
3. 章节列表 `renderChapterItem` 收敛到 3 块 + 单 tag + 删除"💡 快速浏览即可" + 删除 🎯/💡 同时显示逻辑
4. 全书知识点弹窗加 3 个状态过滤器 + 按章节分组
5. 全书总览按 §3.4 五块结构重排
6. 删除"🚀 知识快照"按钮 + 弹窗入口（保留 `showSnapshotsModal` 函数体可不删，留 fallback）

**测试要求**：
- 单元：`tests/test_app_js_render.py`（如现有）覆盖 3 块结构、单 tag 优先级
- 集成：手动验证速读 / 标准 / 研读三模式头部按钮渲染
- 视觉回归：截 3 张图（小屏 / 中屏 / 大屏）

**回退方案**：所有改动按 commit 拆分，单 commit 可 revert。

### 4.2 切片 B：风格调控存储改用户级（动 schema）

**文件范围**：
- `database.py`：新增 `user_preferences` 表（或扩展 user 表）
- 后端 `courses/{id}/sliders/{role}` → `users/{id}/sliders/{role}`
- `static/js/app.js:1521-1551`：API 路径调整 + 数据回填
- 旧数据迁移：把旧的 `course_sliders` 数据按 `user_id` 聚合保留（升级后用户首课时用旧值）

**db-migrator playbook 关键点**（见 `db-migrator/agent.md`）：
- `CREATE TABLE IF NOT EXISTS` 兼容老库
- 不直接 `DROP` 旧表，保留作为 audit
- 加 `last_modified` 字段 + 索引

**prompt-engineer playbook 关键点**：无变化（prompt 不动）

**测试要求**：
- 单元：`tests/test_database.py` 用户偏好 CRUD
- 集成：登录用户 A 调 5 滑块 → 切到课程 B → 仍生效
- 回归：旧课程用户升级后，进入课程默认值非空（迁移正确）

**回退方案**：保留旧路由作为只读 fallback，新数据走新路径。一旦回退可秒切。

### 4.3 切片 C：决策信号化（涉及 prompt，可选）

**动机**：把 `learning_goal` / `core_viewpoint` 两个 LLM 字段收敛为一个 `chapter_summary`，前端挑最好的展示。

**改动**：
- `chunker.py` snapshot prompt 改：要求只输出 `summary` 一条（不再要求双字段）
- 前端：保留兼容（缺字段时正常显示）
- 数据库：双字段保留 5 个版本周期，新数据只填 summary

**回退**：新旧 prompt 数据并存。回退到老 prompt 不破坏老数据。

### 4.4 切片间依赖

```
切片 A (UI) ──┐
              ├──→ 切片 B (存储)   ──→  切片 C (prompt，可选)
切片 B ──────┘
```

A 不依赖 B，可独立上线。B 必须 A 完成后做（避免用户级滑块上线时还要面对学员模式头部 UI 重复）。C 完全独立。

## 五、跨 rein 影响面评估

### 5.1 reading-mentor 视角（产品）

| 改动 | L1/L2/L3 |
|---|---|
| 砍模型配置按钮 | L1 减噪 |
| 头部按钮分组 | L1 减噪 |
| 全书知识点过滤器 | L1 工具好用 |
| 风格调控改用户级 | L2 跨课程体验质变 |
| 全书知识点重构为差量进度 | **L3** 决策辅助（"还差几项到结业"） |

### 5.2 developer 视角（实现）

- 切片 A 主要影响 `static/` 和 CSS，零后端改动
- 切片 B 动 schema + 数据库迁移，按 `db-migrator` playbook 走 `ALTER TABLE`（不 DROP）
- 切片 C 动 prompt，按 `prompt-engineer` playbook 跑 `tests/test_prompts.py` 回归

### 5.3 prompt-engineer 视角

- 切片 C 涉及 prompt 变更：8 角色 × 4 深度 = 32 组合一致回归
- 双字段合并前后需要分别验证 LLM 输出语义不回归
- 旧 prompt 输出仍存在于数据库，前端兼容显示

### 5.4 db-migrator 视角

- 切片 B 唯一动 schema
- 旧 `course_sliders` 数据要按 `user_id` 聚合迁移
- 新表加 `last_modified` + 索引
- 迁移脚本幂等（可重跑）

### 5.5 tester 视角（覆盖计划）

| 切片 | 单元测试 | 集成测试 | 慢测试 |
|---|---|---|---|
| A: UI 瘦身 | `test_render_chapter_3_blocks` `test_single_tag_priority` `test_filter_syllabus` | 手动截图回归 | — |
| B: 用户级滑块 | `test_user_sliders_crud` `test_sliders_migration` | 切换课程保留设置 | 跨课程回归 |
| C: prompt 合并 | `test_chunker_snapshot_summary_only` | — | `tests/test_prompts.py` 全量回归 |

目标覆盖率：切片 A 新增代码 80%+，切片 B 新增代码 90%+。

### 5.6 code-reviewer 视角（审查清单）

- [ ] 没有破坏现有 `app.js:1110` / `1110-1140` 章节渲染流程
- [ ] 没有 `app.js` 模块级全局状态改动（async_tasks / LLM_CONFIG）
- [ ] CSS 全部内联随用，未引入全局污染
- [ ] 所有 escapeHtml 处理不丢失
- [ ] 路由 view 不少（`switchView('model-config')` 通过左导航仍可达）
- [ ] 涉及 prompt 改动的（切片 C）跑过 `tests/test_prompts.py`

## 六、风险评估与回退
