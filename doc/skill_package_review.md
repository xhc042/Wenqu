# 问渠 v1.2 — 书籍 Skill 包引入 产品评审报告

**评审视角**：reading-mentor (产品视角 / UX / L1/L2/L3 定位)  
**评审人**：Mavis (戴 reading-mentor 视角)

---

## 评审一：L1/L2/L3 定位检验

| 问题 | 回答 | 结论 |
|---|---|---|
| 这个功能是帮用户"读完"还是"会用"？ | **"会用"**。Skill 包不是帮用户读完书，而是帮用户在读完之后反复使用书中的知识 | ✅ 符合 L3 |
| 会不会让用户陷入"读完"的焦虑？ | 不会。Skill 包是后台异步生成，用户感知不到延迟，且课程创建后立即可用 | ✅ 不干扰 |
| 能不能帮助用户形成自己的判断？ | 能。Skill 包的 `anti_patterns` 和 `patterns` 鼓励用户批判性思考"什么时候用/什么时候不用" | ✅ L3 特征 |
| 能不能帮助用户输出？ | 能。从 Skill 文件"开始对话"入口，用户可以直接基于结构化知识展开苏格拉底对话 | ✅ L3 特征 |

## 评审二：五个关键问题

### Q1：用户为什么要看 Skill 包？这和看章节摘要有什么区别？

**A**：Skill 包不是"摘要"，而是**结构化的知识资产**。区别在于：
- 章节摘要是"这本书讲了什么"
- Skill 包是"这本书教会了我什么"——框架、原则、技巧、反模式，都是可迁移的

### Q2：三种阅读模式和 Skill 包是什么关系？

**A**：Skill 包是**底层知识资产**，三种模式是**消费策略**：
- 速读 → 消费 `core_frameworks` + `cheatsheet`（快速把握全局）
- 标准 → 消费 `chapters` + `glossary`（系统学习）
- 研读 → 消费 `patterns` + `anti_patterns`（深度探讨）

### Q3：用户会不会觉得 Skill 包太复杂？

**A**：不会。Skill 包对用户是**渐进式曝光**的：
- 第一阶段：课程页只显示"Skill 包生成中/已完成"的状态
- 第二阶段：用户主动点击"Skill 包"标签才看到详细内容
- 第三阶段：熟练用户直接用"用此内容开始对话"入口

### Q4：非技术类书籍怎么办？

**A**：这是**真正的风险点**。小说、散文、诗歌等书籍不适合生成 Skill 包。需要在 prompt 中加入书籍类型检测逻辑：
- 技术书/方法论 → 生成 Skill 包
- 小说/散文/诗歌 → 跳过 Skill 生成，仅保留分章

### Q5：这个功能和现有的速读模式有什么重叠？

**A**：**不是重叠，是互补**。速读模式关注"快速读完一本书的核心观点"，Skill 包关注"把这本书变成可复用的知识工具"。速读的 `chapter_snapshots` 是 Skill 包的输入之一，但 Skill 包还要生成 `glossary`/`patterns`/`anti_patterns` 等速读不需要的内容。

## 评审三：UX 建议

1. **Skill 包入口要轻**：不要在课程首页放太多 Skill 包信息，避免干扰主流程
2. **生成状态要明确**：用户需要知道 Skill 包在后台生成，预计多久完成
3. **"用此内容开始对话"是核心 CTA**：这是 Skill 包→L3 的关键转化点，按钮要醒目
4. **技能地图要可视化**：用标签云/思维导图的形式展示"这本书能学会什么"，比纯文字更有吸引力

## 评审四：Go / No-Go 决策

| 维度 | 评估 | 建议 |
|---|---|---|
| 产品价值 | ⭐⭐⭐⭐⭐ | **Go** — 完全符合 L3 定位，差异化明显 |
| 技术可行性 | ⭐⭐⭐⭐ | **Go** — 基于现有分章逻辑扩展，风险可控 |
| 实施复杂度 | ⭐⭐⭐ | **谨慎 Go** — 需要新增 2 张表 + 1 个引擎 + 前端改造，建议分 5 个 Phase 逐步上线 |
| 资源消耗 | ⭐⭐⭐ | **注意** — LLM 调用量会增加约 30%，需评估成本 |

**最终结论**：**Go，但分阶段实施**。建议先从 Phase 1-2 开始(后端核心逻辑)，验证 Skill 包生成质量和用户反馈后再推进前端。

## 评审五：与 book-to-skill 的差异化竞争分析

| 维度 | book-to-skill | 问渠 Skill 包 |
|---|---|---|
| **目标** | 让 AI Agent 能查询书中知识 | 让 AI 教师能引导学生应用书中知识 |
| **产物** | 静态文件(SKILL.md + chapters/) | 动态教学资产(与苏格拉底对话状态机联动) |
| **复用方式** | `/book-slug chapter5` → Agent 读取文件 | "用此内容开始对话" → AI 教师引导讨论 |
| **核心价值** | "让书成为可查询的工作流工具" | "让书成为可对话的学习伙伴" |
| **差异化** | 面向开发者/AI 用户 | 面向普通学习者 |

**关键洞察**：问渠的 Skill 包不是在做 book-to-skill 的复刻，而是在做 **book-to-mentor**——把书的知识点转化为 AI 教师的教学素材。这才是问渠的独特价值。

## 总结

本次评审从产品定位、用户体验、技术可行性、差异化竞争四个维度对"书籍 Skill 包"功能进行了全面评估。核心结论如下：

1. **完全符合 L3"会用"定位**，不是帮用户读完，而是帮用户读完之后怎么用
2. **与 book-to-skill 有本质差异**，问渠做的是 book-to-mentor，面向教学而非查询
3. **实施风险可控**，建议分 5 个 Phase 逐步上线，后端先行，前端跟进
4. **真正风险点**是非技术类书籍的 Skill 质量和 LLM 调用成本增加

建议进入 Phase 1 实施阶段，优先完成数据库 schema 变更和 `skill_generator.py` 核心逻辑开发。
