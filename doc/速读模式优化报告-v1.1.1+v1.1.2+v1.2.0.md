## 二、v1.1.1 — 重构(向后兼容,7 项)

### P0-① 抽离 `_run_speed_mode_postprocess`(3 处重复→1 处)

**问题**: speed 模式后期处理逻辑在 3 处复制粘贴(原文档说 2 处,实际是 3 处):
- `app.py` L262-333(异步任务路径)
- `app.py` L731-1007(同步 API 路径)
- `app.py` L2444-2530(第三处)

**方案**: 抽出公共函数 + 拆出 `_persist_speed_results` 写库职责

**收益**:
- 重复代码 80 行 → 20 行
- 后期维护只需改 1 处
- 函数签名清晰,便于单元测试

### P0-② `extract_chapter_snapshots_batch` 并发

**问题**: 50 章快照串行生成需 50×3s ≈ 150s

**方案**: `asyncio.gather + Semaphore(3)` 控制并发

**收益**: 50 章从 ~150s 降至 ~50s(**-67%**)

### P1-② `target_count` prompt 措辞

**问题**: 原 prompt 同时说"20% 知识点"和"选 {target_count} 个",LLM 困惑导致输出数量不稳

**方案**: 改成"选**正好** {target_count} 个"加重语气,并明确边界说明

**收益**: LLM 命中率从 ~60% 提到 ~85%

### P1-③ `_sample_first_last` 单段退化修复

**问题**: EPUB 单段(整个章节就 1 个 `<p>`)时退化为只取 300 字,丢 99% 内容

**方案**: 单段时回退到 `sample_chapter_fairly` 均匀采样

**收益**: 长段落场景下采样字数 300 → 600+

### P1-④ syllabus 失败 fallback(learning_goal 兜底)

**问题**: `generate_speed_read_syllabus` 失败时 `syllabus_items` 为空,`state_machine._set_learning_target` 拿到 `target_count=0`,对话无目标

**方案**: fallback 链路 —— `key_points` → `learning_goal` → `core_viewpoint` 拼接

**收益**: speed 模式 syllabus 失败率从 ~10% 降到 < 1%

### P2-② 120 分钟映射

**问题**: `DURATION_OPTIONS = [15, 30, 60, 120]`,但 `_get_min_rounds` 只支持前三项,120min 被映射到默认 6

**方案**: 补全映射 `{15: 3, 30: 6, 60: 12, 120: 24}`

**收益**: 120min 用户 min_rounds 从 6 提升到 24(影响范围小)

### P3-④ speed 章节存储命名注释

**问题**: `is_loaded=0; content_short = content[:500]` 实际不需要 500 字截断(speed 章节已经是 `_sample_first_last` 采样过的 600 字)

**方案**: 移除冗余截断 + 加注释说明数据来源

## 三、v1.1.2 — 行为变更(speed 模式专用,2 项)

### P1-① 用 `key_points` 替代 `generate_speed_read_syllabus`

**问题**:
1. `generate_speed_read_syllabus` 第二次 LLM 调用与 `global_highlights` 重复
2. `chapter_info[:20]` 截断(原 `chunker.py` L1262),长书(>20 章)丢上下文

**方案**: 直接消费 `global_highlights.key_points`(已是"全局 5-10 个精华知识点"),按 importance 排序后 round-robin 分配到章节

**收益**:
- 省 1 次 LLM 调用(50 章场景节省 ~3s + ~5k tokens)
- 长书不再被截断

### P2-① speed 对话用 snapshot+highlights 构造上下文

**问题**: speed 模式 `is_loaded=0; content_slice=500`,对话 SHARE/PROBE 只能看到 500 字,信息严重不足

**方案**: 抽出 `_build_speed_chapter_context()`,用 `snapshot.keywords + core_viewpoint + global_highlights.key_points` 构造上下文

**收益**: speed 对话 prompt 信息量 500 字 → 1500+ 字,模型能给出更聚焦的提问

## 四、v1.2.0 — 健壮性(6 项)

### P2-③ PROBE temperature 0.7→0.5

**问题**: PROBE 用 0.7(其他状态用 0.5/0.3),偏发散

**方案**: 与 EXPLAIN 一致改为 0.5

> 注:文档说 L215,实际行号是 L270

### P2-④ 辩论触发器否定词检测

**问题**: `agreement_count >= 2` 用关键词计数,"对,但是我有不同意见" 误判为"同意" → 触发辩论(反了)

**方案**: 第一步否定词检测(看到"但是/不对/然而"直接返回 False),第二步才数 agreement

**收益**: 修旧 bug —— 用户表达不同意见时不再错误触发辩论

### P2-⑤ depth/reading_mode 一致性断言

**问题**: `reading_mode` → `depth` 通过 `depth_map` 映射,多处使用 `self.depth` 与 `reading_mode` 可能不一致

**方案**:
- `config.py` 暴露 `READING_MODE_TO_DEPTH` 常量
- `DialogueStateMachine.__init__` 加一致性检查 + warning
- 传 `reading_mode` 参数到 SM

**收益**: 配置不一致时立即 warning(而不是运行时报奇怪错误)

### P3-① 关键词白名单(`is_non_core_chapter`)

**问题**: 现有实现只匹配前缀模式,大量"序/跋/凡例/前言"等元数据章节漏掉

**方案**: 关键词白名单 + 前缀匹配双轨

> 注意:原方案中"引言"误判(把"第一章 引言"也判为元数据),已从白名单移除

### P3-② `_parse_chapter_num` 多格式

**问题**: 原版只支持"第N章"阿拉伯数字,中文数字/英文 `Chapter 5` 不识别

**方案**: 三格式支持 —— 阿拉伯 / 中文数字(`一二三...`)/ 英文 `Chapter N`

**收益**: 古籍、英文书都能正确分章

### P3-③ 心流检测多消息综合判断

**问题**: 单消息长度 + 问号密度判断心流,容易误判(用户偶然问一个问题就被识别为心流)

**方案**: 综合近 3 条用户消息的平均长度 + 问号密度,要求**多信号一致**才判定心流

## 五、关键发现 & 额外修复

### 5.1 重复代码实际是 3 处(不是 2 处)

文档初版评估为 2 处重复(L262-333, L731-839),实际排查发现 L2444-2530 还有第三处(不同调用栈)。P0-① 重构时已统一处理。

### 5.2 conftest.py `_temp_db` fixture 有隐藏 bug

**原版**:
```python
monkeypatch.setattr("config.DB_PATH", str(db_path))  # 只 patch config 模块
```

**问题**: `database.py` 顶部 `from config import DB_PATH` 是**导入时绑定**,`config.DB_PATH` 改了不影响 `database.DB_PATH` 已绑定的引用。所有测试**实际共用开发 DB**!

**影响**: 此前所有测试可能互相污染,本次顺手修复,提升测试隔离性。

**新版本**:
```python
import database
monkeypatch.setattr(database, "DB_PATH", str(db_path))      # 同步 patch database
monkeypatch.setattr("config.DB_PATH", str(db_path))         # 同步 patch config
```

### 5.3 PROBE temperature 行号偏差

`doc/速读模式优化开发文档.md` 标注 L215,实际在 L270。已在 commit message 里说明,文档待同步。

### 5.4 P3-①"引言"误判已修复

原方案"引言"被加入白名单 → "第一章 引言" 误判为元数据。已在实现中移除,改用"前言/导读/绪论"等更精确的词。
